## 라우팅

- **실행 확인.** 홈, 상태 확인, 지정 종목 조회는 200을 반환했다. 등록된 주문 경로에 `GET /api/orders`를 보내면 정적 파일 조회로 넘어가 404가 반환됐다. 코드상 상태 확인 경로는 메서드를 제한하지 않고, 미등록 경로의 POST에도 405를 준다. 경로 존재 여부를 먼저 판정하고 메서드가 맞지 않으면 405와 `Allow`를 보낸다. [상태 확인 경로](<C:/Users/custa/OneDrive/Desktop/ui test page/hts/server.mjs:57>) · [라우팅 종료 분기](<C:/Users/custa/OneDrive/Desktop/ui test page/hts/server.mjs:81>) · [RFC 9110 §15.5.6](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.5.6)
- **코드·기존 테스트 확인.** 서버는 잘못된 수량과 디스크 기록 실패를 모두 400으로 응답한다. 기존 디스크 장애 테스트도 이 400을 기대하므로 테스트가 통과한다. 클라이언트가 입력을 고칠 상황과 서버 상태를 확인할 상황을 구분할 수 있도록 오류 코드를 분리한다. [HTTP 오류 매핑](<C:/Users/custa/OneDrive/Desktop/ui test page/hts/server.mjs:88>) · [장애 테스트 기대값](<C:/Users/custa/OneDrive/Desktop/ui test page/hts/tests/server.test.mjs:57>)
- **코드 확인.** 서버 옵션은 80번 포트를 허용하지만 Host 비교에는 항상 포트 번호가 필요하다. 기본 포트를 생략한 정상 로컬 주소로 열면 403이 될 수 있다. 허용하는 로컬 호스트 이름과 실효 포트를 개별 비교한다. [포트 범위](<C:/Users/custa/OneDrive/Desktop/ui test page/hts/server.mjs:14>) · [호스트 검사](<C:/Users/custa/OneDrive/Desktop/ui test page/hts/server.mjs:55>)

## 실제 고객용 HTS에 추가할 검증

현재 명시된 제품 범위는 로컬 공동 모의계좌다. 실제 고객용 서비스라면 **계좌별 조회·주문·취소 권한**, **체결번호별 수량·가격·시각을 보존하는 원장과 잔고 대사**, **거래소의 주문 접수·부분체결·취소 확인이 엇갈릴 때의 상태 처리**가 출시 판단에 필요하다. 현재 구현은 주문별 누적 체결 수량과 평균 가격을 유지하고, 오래된 완료 주문은 정리한다. 로컬 모형에서 의도한 공동 계좌와 보관 범위를 고객 거래 요구와 구분해 평가했다.
