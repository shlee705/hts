# PULSE mini HTS

KOSPI 상장 10종목의 검색, 관심종목, 현재가·호가·체결, 주문, 잔고를 갖춘 로컬 웹 HTS입니다. Node.js 20 이상에서 외부 패키지·API 키 없이 실행합니다.

## 실행

`hts` 폴더에서 실행합니다.

```powershell
npm.cmd start
```

브라우저에서 <http://localhost:5173>을 엽니다. 기본 실행은 개정 제안서의 결함 14개를 모두 활성화합니다. 별도 `npm install`은 필요 없습니다.

F-02는 지정가 주문의 체결 수량과 관계없이 적용됩니다. 매수 예수금은 주문 지정가 × 실제 체결 수량만큼 줄고, 매도 예수금은 같은 계산으로 늘어납니다. 주문 화면은 V-02로 인해 1주를 거부하므로 2주 이상으로 확인할 수 있습니다.

V-04로 인해 모든 종목에서 당일 가격 범위 안의 정수 지정가는 호가 단위에 맞지 않아도 매수·매도 주문으로 접수됩니다. 예를 들어 100원 단위 가격대에서 193,003원으로 2주 매수를 넣으면 주문내역에 그 가격과 수량이 기록됩니다. 미체결 상태에서는 386,006원이 예약되고, 전량 체결되면 F-02에 따라 예수금에서 같은 금액이 차감됩니다.

```powershell
# 10종목을 250ms마다 갱신
npm.cmd run dev -- --tick-ms 250
```

기본 포트 5173, 갱신 간격 1000ms, 시드 20261116입니다. `PORT`, `TICK_MS`, `SEED`, `HTS_DATA_DIR` 환경변수도 지원합니다. `--tick-ms` 범위는 50~60000ms입니다. 서버는 `127.0.0.1`에만 바인딩합니다. 다른 데이터 폴더에서 같은 시드·초기 종가·갱신 간격·틱 수를 사용하면 시장 경로를 재현할 수 있습니다. 주문은 호가 잔량과 계좌에 영향을 주지만 시장 난수열을 소비하지 않습니다.

## 기준 데이터와 거래일

2026년 11월 5일부터 18일까지의 보관 시세에서 삼성전자, SK하이닉스, 기아, 삼성에피스홀딩스, 두산, 현대차, NAVER, KB금융, 삼성중공업, 두산에너빌리티를 사용합니다. 발행주식수와 기준 종가는 11월 18일 값입니다. 야간·주말의 보간 분봉과 선정 종목으로 산출한 지수 시계열을 `reference/continuous/`에 저장합니다. 저장소 최상위에서 `node hts/reference/build-continuous.mjs`로 재생성할 수 있습니다.

11월 18일 장 마감 이후부터 로컬 시장은 주말과 공휴일을 포함해 연속 거래합니다. 일봉과 당일 가격 제한의 기준은 한국시간 오전 9시입니다. 종료할 때 현금·잔고·주문과 마지막 가격을 저장하고, 재시작 시 비어 있는 분의 체결가와 거래량을 시드로 생성해 차트와 지수에 반영합니다. 정상 종료는 Ctrl+C를 사용합니다.

새 데이터 폴더는 10종목 시장을 바로 저장합니다. 기존 100종목 폴더를 열면 원래 시세와 계좌 기록을 보관하고 `kospi10/` 아래에서 10종목 시장을 엽니다. 보유 종목과 주문내역의 종목이 모두 선정 범위에 있으면 잔액·보유량·주문·예약 및 주문 결과를 복사합니다. 제외된 종목이 있으면 해당 하위 폴더에 새 모의 계좌를 만들고 시작 시 콘솔에 알립니다. 이전 시장의 틱과 차트는 새 지수에 합산하지 않습니다.

데이터 폴더의 파일

| 파일 | 내용 |
|---|---|
| `market-state.json` | 매 틱/주문 직후 원자적으로 교체하는 가격·계좌 체크포인트 |
| `ticks.jsonl` | 틱·주문·종료 시점의 10종목 가격·지수, 발생한 내부 이벤트 기록 |
| `ticks.1.jsonl`~`ticks.3.jsonl` | 회전된 이전 기록. 파일당 약 16MiB, 총 약 64MiB로 제한 |
| `candles.json` | 종목별 여섯 주기의 최근 봉 100개씩. 매분과 정상 종료 때 교체하며, 재시작 시 이후의 시세 로그를 이어 붙입니다. |
| `order-receipts/` | 최근 500건에서 빠진 완료·취소 주문과 확정 거절의 요청 ID별 결과. 오래된 재시도도 판별하며 저장 공간은 주문 수에 따라 늘어납니다. |
| `server.lock` | 실행 PID 기록. 운영체제의 독점 잠금으로 동시 기록을 막습니다. |

손상된 저장 파일을 발견하면 임의로 새 계좌를 생성하지 않고 시작을 중단합니다. 영구적인 기록 실패 시에도 시세를 계속 배포하지 않고 종료합니다. 실험 초기화는 기존 데이터 삭제 대신 새로운 `--data-dir`를 지정하면 됩니다.

## 기능

- 종목명/코드 검색, 시총/등락률/거래량 정렬, 관심종목 추가·제거. 관심종목은 브라우저 `localStorage`에 저장합니다. `/` 키로 검색창에 이동합니다.
- 트레이딩은 `/`, 보유잔고·주문내역·미체결 취소는 `/account`, 테스트 예수금 충전·인출은 `/cash`입니다.
- 현재가 행에서 해당 가격의 잔량을 표시합니다. 가격대 잔량이 모두 체결되면 그 가격에 추가 주문을 체결시키지 않습니다. 시장가를 선택하면 주문가격과 예상 주문금액을 숨깁니다.
- 1·3·5·30분, 1시간, 일봉을 한국시간 기준으로 집계합니다. 종목과 모의 KOSPI 10 지수 차트는 화면 너비에 맞춰 봉을 표시합니다. 종목 차트의 ‘자세히 보기’ 또는 지수 버튼으로 확대 창을 엽니다. 차트를 좌우로 밀거나 하단 슬라이더로 과거를 탐색하고, +·−로 표시 범위를 조절합니다. 슬라이더에 초점을 두고 방향키로 이동하거나 ‘최신으로’를 눌러 실시간 시세로 돌아갈 수 있습니다. 차트 설정에서 캔들과 종가선을 전환할 수 있습니다.
- 재시작해도 같은 시간 구간의 분봉과 시간봉은 이어집니다. 분봉·시간봉의 흰색 점선은 매일 한국시간 오전 9시에 표시하고, 거래일은 오전 9시에 바뀝니다.
- 기준 이력에 모든 보관 거래일과 진행 중인 거래일의 봉을 이어 붙입니다. 종목과 지수 차트의 ‘전체 기간’으로 첫 봉부터 최신 봉까지 보고, ‘최신으로’로 돌아갑니다.
- 시가총액은 종목의 현재가와 기준일 발행주식수를 곱한 금액입니다.
- 충전·인출은 서버가 요청 번호와 잔액 버전을 검증하고 계좌를 저장한 뒤 `ok: true`와 새 잔액을 응답합니다. 인출 가능 금액에서는 미체결 매수 예약금을 제외합니다. 결과를 확인하지 못했을 때는 같은 요청 번호와 버전으로 재확인합니다.
- 지정가/시장가 매수·매도, 부분 체결, 미체결 잔량 취소, 주문내역·보유잔고·평가손익.
- 최초 현금은 1억 원이며 초기 보유종목은 없습니다. 매수 미체결은 현금을, 매도 미체결은 보유 수량을 예약해 중복 사용을 방지합니다.
- 화면은 각 방향의 최우선 10단계를 표시합니다. 시장가와 지정가는 전체 가격제한폭의 호가를 가격순으로 소진하며 시장가 잔량은 매수 시 상한가, 매도 시 하한가에 대기합니다. 시장가 매수 자금은 상한가를 기준으로 보수적으로 검사하고 실제 체결가만 차감합니다. 지정가는 조건에 맞으면 시간 순으로 체결합니다.
- 지정가가 당일 허용 범위 밖이면 입력 완료 또는 주문 시 상한가·하한가로 자동 보정합니다. 기준 범위는 전일 종가의 ±30%입니다. 호가창은 각 가격에 해당하는 호가 단위(1·5·10·50·100·500·1,000원)를 적용합니다. 경계는 2,000·5,000·20,000·50,000·200,000·500,000원입니다. 예를 들어 199,900원 다음은 200,000원, 그다음은 200,500원입니다. 주문 단위 안내는 입력한 가격을 따르며 V-04에 따른 주문 접수와 체결 내역은 보존됩니다. 수수료·세금·거래일 캘린더·공매도·가격 우선 매칭·실제 거래소 연결은 구현 범위에 포함하지 않습니다. [한국거래소 주식 호가 단위](https://global.krx.co.kr/contents/GLB/06/0602/0602010201/GLB0602010201T3.jsp)
- 주문 폼은 선택 종목과 호가가 일치할 때 활성화됩니다. 서버 응답이 늦으면 HTTP 202와 요청 ID를 반환하고 화면이 최종 결과를 조회합니다. 동일 요청의 재시도는 기존 결과를 돌려주며 내용이 다르면 409입니다. 화면 이력은 최근 500건, 미체결 슬롯은 100개입니다. 업데이트 전 이미 삭제된 주문의 요청 ID는 복원할 수 없습니다.

## 가격 변동과 내부 이벤트

평상시에는 가격이 중심 가격으로 되돌아오는 모형을 사용합니다. 중심은 세션 시작 현재가이며, 호재·악재가 있을 때만 점진적으로 이동합니다. 평상시 한 틱의 실제 가격 변화는 최대 1호가입니다. 내부 가격의 범위는 중심의 ±0.15%(최소 1호가)이며, 화면 가격은 호가 단위 반올림 때문에 최대 0.5호가 차이가 추가될 수 있습니다. 무제한으로 누적되는 랜덤 워크는 사용하지 않습니다.

각 종목은 최초 45~120초 사이에 이벤트를 시작하고, 이벤트 종료 후 90~180초를 기다린 다음 새 이벤트를 발생시킵니다. 모든 종목이 동시에 움직이지 않도록 시작 시점·종류·강도를 별도의 시드 기반 난수열로 정합니다.

| 내부 이벤트 | 발생 가중치 | 중심 가격 목표 이동 | 지속 시간 |
|---|---:|---:|---:|
| 호재 | 40% | +0.3~0.8% | 25~45초 |
| 악재 | 40% | −0.3~0.8% | 25~45초 |
| 매우 호재 | 10% | +1.2~2.5% | 25~45초 |
| 매우 악재 | 10% | −1.2~2.5% | 25~45초 |

목표가는 즉시 점프하지 않고 완만하게 이동합니다. 이벤트 동안 가격 잡음과 체결량도 증가하며, 종료 후에는 새 가격대를 중심으로 잔잔한 움직임을 유지합니다. 실제 체결가격은 호가 단위, 잡음, 기존 ±30% 제한에 따라 목표 이동률과 다를 수 있습니다.

시간은 서버에서 처리한 틱의 `tickMs`를 누적한 시뮬레이션 진행 시간입니다. 50ms 갱신은 1000ms 갱신보다 이벤트를 20배 빨리 발생시키지 않습니다. 잡음도 진행 시간의 제곱근에 비례하도록 보정했습니다. 재시작할 때는 비어 있는 분의 가격 경로를 별도로 복원합니다.

이벤트는 화면 뉴스로 노출하지 않습니다. 진단할 때 `ticks.jsonl`의 `marketEvents`, `market-state.json`의 `simulation.recentEvents`를 확인할 수 있습니다. 최근 이벤트 메모리는 100건으로 제한합니다. 세션 종료 시 현재 가격만 다음 기준가로 이어지며, 진행 중 이벤트는 다음 세션에서 새로 시작합니다. 조정 값은 `market.mjs`의 `PRICE_MODEL`, `EVENT_TYPES`, `movePrice()`에 모았습니다.

## 모의 KOSPI 10 지수

KPI10은 2026년 11월 18일 종가를 1,000점으로 두는 모의 지수입니다. 값은 1,000 × 구성 10종목의 현재 시가총액 합계 ÷ 같은 종목의 기준일 시가총액 합계입니다. 과거 분봉에서 각 종목의 같은 분 시가·고가·저가·종가에 발행주식수를 곱해 각각 합산합니다. 분봉 고가·저가는 개별 종목 극값을 종합한 추정치이며, 상위 주기의 봉은 1분 지수봉을 집계합니다. 거래량은 구성 종목 주수의 합입니다.

## 성능 설계와 검증

시세/주문/기록은 전용 Worker Thread 한 곳에서 순차 처리하고 HTTP/SSE 처리는 메인 스레드에서 수행합니다. 파일 쓰기는 비동기이며 끝나기 전 다음 틱을 쌓지 않습니다. 저장이 완료된 후에만 시세를 배포하고 주문 성공을 응답합니다. Windows/OneDrive의 일시적인 파일 점유는 이전 체크포인트를 유지한 채 최대 8번 재시도합니다.

SSE는 10종목 요약과 각 연결이 선택한 1종목 상세만 전송합니다. 캔들 이력은 종목·주기를 선택할 때와 새 봉이 시작될 때 조회하며, 틱마다 선택 종목의 최신 봉만 실시간 전송합니다. 주문은 변경분만 전달합니다. 느린 클라이언트는 이벤트 종류별 최신값만 유지하며 주문 업데이트를 전체 스냅샷으로 병합합니다. 10초 이상 막힌 연결은 끊고 재접속 시 최신 상태를 다시 읽습니다. SSE 연결 상한은 200개, 대기 중 요청은 256개입니다.

브라우저는 10개의 종목 행을 재사용하고 변경 텍스트만 갱신합니다. 렌더링은 최대 10fps로 합치고 차트·체결·주문 버퍼에는 상한을 둡니다. 사용자 입력 영역을 틱마다 재생성하지 않습니다.

```powershell
npm.cmd test
npm.cmd run bench

# 100개 실시간 연결, 50ms 갱신으로 60초 측정
$env:BENCH_SECONDS='60'
npm.cmd run bench
```

`bench` 기본값은 30초/100개 클라이언트입니다. `BENCH_CLIENTS`로 1~150개를 선택할 수 있습니다. 부하 테스트는 별도 데이터 폴더/18380 포트에서 실행되며 종료 후 종가를 저장합니다. 실제 파일 I/O, 조회 요청, 연속 매수·매도, 정지된 클라이언트를 함께 포함합니다. 종료 조건은 오류 0건, 연결/대기 요청 회수, 15틱/초 이상, 주문·조회 p99 500ms 미만, RSS 512MiB 미만입니다. 측정 결과는 `qa/load-report.json`에 기록합니다. 상세 검증 범위는 `qa/verification.md`를 참고하세요.

## 로컬 API

| 요청 | 동작 |
|---|---|
| `GET /api/state?symbol=005930` | 10종목 요약, 선택 종목 상세, 공동 계좌/주문 스냅샷 |
| `GET /api/events?symbol=005930` | SSE: `state`, `tick`, `detail`, `account`, `orders`, `closing` |
| `POST /api/orders` | JSON `{code,side:"buy"/"sell",type:"limit"/"market",quantity,price,requestId}` |
| `GET /api/orders/requests/:requestId` | 요청 결과 조회. 완료 시 주문, 주문 거절 422, 접수 이력 없음 404 |
| `GET /api/candles?symbol=005930&period=1m` | 최근 봉, 시각·시가·고가·저가·종가 순. 주기는 1m/3m/5m/30m/1h/1d |
| `GET /api/cash` | 서버 예수금, 인출 가능액, 현재 변경 버전 |
| `POST /api/cash` | JSON `{direction:"deposit"/"withdraw",amount,revision,requestId}`. 서버가 저장을 확인한 뒤 응답 |
| `POST /api/orders/P000001/cancel` | JSON `{}`로 미체결 잔량 취소 |
| `GET /api/health` | 틱, 연결 수, 대기 요청, RSS, 이벤트 루프 p99, 파일 재시도 수 |

HTTP 상태를 통한 검사와 UI를 통한 에이전트 평가 모두 가능합니다. API는 로컬에서 로그인 없이 공동 계좌를 조작합니다. 서버는 데이터·테스트·설정 파일을 정적 경로로 제공하지 않습니다.

## 파일 구성

`server.mjs`는 HTTP·SSE, `market-worker.mjs`는 시세 주기·기록·복구, `market.mjs`는 난수/체결/계좌, `public/`은 화면, `tests/`는 엔진·통합·부하 검사입니다. 번들러와 런타임 의존성이 없어 소스 수정 후 서버 재시작/브라우저 새로고침으로 반영됩니다. 기존 Astra 사이트는 상위 폴더에서 `npm run dev:astra`로 실행합니다.
